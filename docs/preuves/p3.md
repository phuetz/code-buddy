### Rêve

Commande : `scripts/preuves/p3.sh dream`. Le script lance le CLI `buddy server --port <port-libre>` par le shim `tsx` du dépôt, `HOST=127.0.0.1`, `CODEBUDDY_SENSORY=true`, un jeton synthétique temporaire et `CODEBUDDY_DREAM_EVERY=20`. Il vérifie `/api/health`, puis fait tourner le daemon Rust sur le WAV fixture ; tout le trafic reste sur loopback. Après les événements audio, le harnais attend jusqu’à 30 secondes que `dream:recent` soit écrit en mémoire avant d’arrêter le serveur. Il signale un échec si la promotion n’arrive pas dans ce délai.

### Entraînement de la perception

Commande : `scripts/preuves/p3.sh vision-train`, qui exécute le CLI réel :

```text
CODEBUDDY_VISION_TRAIN=true node_modules/.bin/tsx src/index.ts vision-train --images _qa/p3/images --labels _qa/p3/labels.json --out _qa/p3/out
```

L’environnement renseigne l’interpréteur et le modèle YOLO locaux via `CODEBUDDY_YOLO_PYTHON` et `CODEBUDDY_YOLO_MODEL`; la configuration Ultralytics jetable coupe sa synchronisation. Une première tentative avec le Python système échouait réellement avec `ModuleNotFoundError: No module named 'ultralytics'`. Le rejeu a été refait avec le runtime local disponible.

Sortie brute mesurée (chemins locaux omis) :

Elle prouve que le CLI appelle YOLO et produit un benchmark, pas que YOLO trouve une personne ni que le classement de défauts est pertinent. Verdict maintenu 🧪.

## Rejeu

- Tout refaire : `scripts/preuves/p3.sh all`.
- Une surface : `scripts/preuves/p3.sh nervous|dream|rules|vision-train`.
- `scripts/preuves/p3-prepare.py` ne crée que des fixtures et réglages YOLO sous `_qa/p3/` ; profils `HOME` et `USERPROFILE` sont dirigés vers ce dossier.
- Les dépendances Rust utilisent `CARGO_NET_OFFLINE=true` ; fournir `CARGO_HOME` et `RUSTUP_HOME` pointant vers des caches Rust disponibles en lecture. Le script impose `HOME`/`USERPROFILE` jetables et refuse le rejeu Rust sans ces variables. Le serveur et le pont n’écoutent que sur loopback. Fournir explicitement `P3_YOLO_PYTHON` et `P3_YOLO_MODEL` pour `vision-train` ou `all` : aucun chemin n’est repris du profil appelant.

## Correctif de rapport sans scènes scorées

Pendant la tentative YOLO initiale, toutes les scènes ont échoué faute de module Python. Le CLI a alors rendu `Scenes: 0`, `Accuracy: 0%` et « None — perception matched ground truth ». J’ai corrigé ce faux succès séparément, sans masquer l’échec de la perception.

- Rouge initial : commande ciblée Vitest, `tests/vision-train/report.test.ts` : 2 tests, 1 échec. L’assertion `no scored scenes` a reçu le rapport vide qui prétendait à une correspondance.
- Après correction : `tests/vision-train/report.test.ts` + `tests/vision-train/scorer.test.ts` : 2 fichiers, **11 tests réussis**.
- Mutant (rendu précédent remis) : 1 test échoue de nouveau ; l’assertion montre « None — perception matched ground truth across the curriculum. »
- CLI réel rejoué avec interpréteur Python sans Ultralytics : `ModuleNotFoundError: No module named 'ultralytics'`, rapport désormais `Accuracy: not measured (no scored scenes)` / `Mean count error: not measured` / `Weak spots: Unavailable — no scenes were successfully scored.` Le journal annonce toujours `1 scene(s) failed`; le CLI conserve explicitement le verdict « not measured » au lieu de transformer l’échec en correspondance.

Sortie brute utile du CLI après correction :

```text
[1/1] scene.png — FAIL: YOLO runtime exited with code 1: ModuleNotFoundError: No module named 'ultralytics'
- Scenes: **0**
- Accuracy: not measured (no scored scenes)
- Mean count error: not measured
## Weak spots
- Unavailable — no scenes were successfully scored.
WARN 1 scene(s) failed to produce an image/perception (excluded from the benchmark).
```

Test lancé avec `vitest run --configLoader runner` et un préchargement de `__dirname` dans le seul harness temporaire, car le `node_modules` partagé est en lecture seule. La correction est dans un commit local français séparé ; elle ne rend pas la preuve YOLO plus large que la scène vide décrite plus haut.

## Ce que je n’ai pas pu vérifier

- Détection YOLO positive sur des scènes réalistes étiquetées, classement de faiblesses sur plusieurs conditions, génération d’images du mode curriculum, réentraînement effectif des poids et ajout de résultats au CKG.
- Caméra, microphone réel, AT-SPI et capture écran : cette campagne a utilisé un WAV fixture et le daemon compilé sans features matérielles activées.
- Le health API est `unknown` dans le serveur temporaire ; ce test vise le pont sensoriel et le rêve, pas un fournisseur de chat.
- Aucun LLM n’était nécessaire dans les quatre chemins exercés ; Ollama n’a pas été sollicité.
