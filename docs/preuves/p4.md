## Correctif séparé : erreur de `ws search`

La première exécution réelle sans configuration rendait le refus du moteur comme rejet non géré, écrivait un rapport de crash dans le profil temporaire et conseillait une reprise de session. J’ai ajouté un test avant le correctif : le test ciblé a échoué sur ce rejet (1 échec / 1 test voisin vert). Le correctif affiche le message métier, fixe `process.exitCode=1` et termine l’action. Après correctif : 2/2 tests verts; mutant retirant le correctif : le nouveau test redevient rouge (1/2); après restauration : 2/2 verts. Le rejeu réel final rend bien le message attendu, code 1, stderr vide, sans rapport de crash.

Test ciblé : `npx vitest run --configLoader runner --config <config temporaire> tests/workspace/ws-cli.test.ts`. `--configLoader runner` et la copie temporaire de config évitent l’écriture Vite dans le lien `node_modules` partagé en lecture seule. Le profil Vitest est lui aussi jetable. Le test vert final est inclus dans `p4.sh`.

Commit correctif local distinct : `e197572ac`. Pas de production supplémentaire modifiée pour les preuves.

## Rejouer

`bash scripts/preuves/p4.sh` rejoue le canari loopback, l’échec de la commande de génération, les aides, les invocations sûres sélectionnées, le test ciblé final et les deux échanges MCP stdio. Pour garder les captures complètes dans un emplacement choisi, définir `P4_OUTPUT_DIR` vers un nouveau répertoire vide. Le script refuse d’écraser un chemin déjà présent.
