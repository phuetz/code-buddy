# Brouillon 2 — Une amélioration doit laisser une preuve

Statut : brouillon français non publié. Référence technique : candidat Code Buddy01fc0dbd3.

« L’agent s’améliore » mérite une explication vérifiable.

Dans Code Buddy, une première voie travaille les leçons, outils authored et skills. Deux procédures proches peuvent être proposées à la consolidation : les skills épinglés sont préservés et les attentes couvertes doivent rester présentes. Ce contrôle textuel est utile, mais une vraie utilisation doit encore confirmer la qualité de la procédure.

Une autre voie, `buddy evolve`, prépare et évalue des variantes de code dans des worktrees. On peut examiner les variantes et leur différence avec une référence. Le moteur ne les fusionne pas automatiquement.

La référence [Darwin Gödel Machine de Sakana](https://sakana.ai/dgm/) inspire cette sélection empirique. Elle ne permet pas d’attribuer à Code Buddy les scores publiés par les chercheurs.

Pour moi, une amélioration racontable doit montrer la tâche de départ, le changement, le résultat observé et les régressions recherchées. Un score hors ligne n’est qu’une partie de ce dossier.

Note éditoriale : accompagner d’un diff et d’une recette réelle avant publication. [Activation et limites](../../learning-mechanisms.md).
