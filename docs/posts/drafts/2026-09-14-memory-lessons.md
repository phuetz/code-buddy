# Brouillon 1 — Retenir ce qui aide vraiment le prochain travail

Statut : brouillon français non publié. Référence technique : candidat Code Buddy01fc0dbd3, revue de source du 14 septembre2026.

Un agent de développement utile devrait éviter de nous faire répéter les conventions d’un dépôt à chaque session.

Dans Code Buddy, nous distinguons la mémoire, les leçons et les procédures. La mémoire peut conserver une convention de projet. Une erreur peut produire une leçon candidate, à examiner avant activation. Un skill décrit une méthode de travail réutilisable.

Exemple : un diagnostic échoue parce qu’il utilise le mauvais profil. La leçon utile explique la vérification à refaire et son contexte. Elle ne transforme pas cet incident en règle universelle.

La file de revue est visible avec `buddy lessons candidate list`. Les leçons actives se consultent séparément avec `buddy lessons list`. Cette distinction permet de discuter ce que l’agent propose avant de le considérer comme acquis.

L’inspiration [Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus) concerne notamment le contexte conservé dans des fichiers. Le mécanisme de revue de Code Buddy est sa propre réalisation.

Le test décisif reste le prochain travail réel : la bonne information est-elle retrouvée et utilisée ?
